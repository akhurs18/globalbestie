# Global Bestie — Deep QA Audit & UX Review

**Date:** 4 July 2026
**Scope:** Storefront (globalbestiepk.com), Admin Portal (/portal), Ads Portal (/ads)
**Method:** Live end-to-end testing (real browser, real orders placed & cleaned up) + full source review of `assets/app.js`, `portal.html`, `netlify/functions/*`.

A real test order (`GB-2026-07045838`) was placed through checkout, accepted and advanced in the portal, then cancelled — so every stage of the order lifecycle was exercised on production. A QA product was created in the catalog editor. All test artifacts were cleaned up.

---

## 1. What works well

The core commerce flow is solid. Browsing, product quick-view, add-to-cart, cart drawer with per-item variant/quantity, checkout with PKR advance math, order creation (`/api/orders` → 200), and the customer tracking page all function correctly end-to-end. The portal's order command drawer (accept → sourcing → shipment, cancel with no-refund detection), the "Needs your attention" triage view with SLA badges, the catalog publish/draft controls, and the "Production readiness" checklist are genuinely well designed. The ads portal degrades gracefully — it clearly explains the Meta permission error rather than showing a blank screen.

## 2. Bugs & issues found

Severity: **P0** = blocks money/data safety, fix before more traffic · **P1** = broken feature · **P2** = polish.

### P0 — Admin auth bypass (FIXED)
`requireAdmin()` in `netlify/functions/_shared/supabase.js` authorized **any** request whose `Cookie` header merely *contained* the string `gb_team_session=` — it never validated the token. Confirmed live: sending a forged cookie `gb_team_session=forged-not-a-real-session` to `/api/admin/dashboard` returned **HTTP 200** with the full admin payload — every order, all customer PII (names, phones, emails, addresses), settings, and marketing data. Any visitor could read the entire back office.

**Fix shipped:** `requireAdmin` is now `async` and validates the token against the `team_sessions` table (checking expiry), the same way `currentTeamMember` does. All 31 admin/ads/scraper endpoints were updated to `await` it. The shared-secret Bearer path is unchanged.

### P0 — Placeholder bank details shown at checkout (FIXED)
Checkout displayed live "transfer here" bank details of **Meezan Bank / 0210-0000-000000 / PK00MEZN0000000000000000** — the demo placeholders. A customer following instructions would wire their 50% advance to a non-existent account. There was only an admin-side console warning; nothing protected the customer.

**Fix shipped:** when the settings row is still the placeholder, checkout now hides the fake account entirely and shows a "Get transfer details on WhatsApp" panel instead. Once the real bank row is saved in Supabase, normal details render automatically. *(This is a stopgap — the real fix is still to enter the live bank details; see §4.)*

### P1 — Account sign-in (WhatsApp OTP) is broken on live
`POST /api/auth/request-otp` returns **HTTP 503** ("Account login is still being set up") because the `otp_codes` table hasn't been created in Supabase. Sign-in cannot complete. The frontend does surface the error as a toast, so it's handled gracefully, but the feature is unusable. **Action:** run the OTP/auth table migration in Supabase (see §4).

### P1 — Product editor silently rejected valid prices (FIXED)
The catalog "Customer price PKR" input used `step="100"`, so any price not divisible by 100 (e.g. 15,750) failed the browser's native number validation and the **Save** button did nothing — no error, no toast. Confirmed with price `12345`. **Fix shipped:** changed to `step="1"`.

### P2 — Console exceptions on navigation (FIXED)
Every route change and some product opens logged `InvalidStateError: Transition was aborted because of invalid state`. Cause: the View Transitions API rejects `.ready`/`.finished` when a transition is already running (fast taps), and those rejections were unhandled. **Fix shipped:** the route transition now swallows the `.ready` rejection and the product-morph transition catches `.finished`.

### P2 — Missing-variant checkout block was easy to miss (FIXED)
Checkout correctly blocks when a shade/size is required but empty — but the only feedback was a toast that slides away as the cart drawer opens over it, so it reads as "the button is broken." **Fix shipped:** the specific variant field now gets a red shake highlight, scrolls into view, and takes focus; the highlight clears as soon as the customer types.

## 3. UI / UX recommendations (not yet implemented — proposed)

These are larger, design-level changes. They're deliberately left as recommendations rather than shipped blind, because the storefront CSS is ~17.5k lines and these deserve a review pass before merging.

**Storefront**
- The hero and category images are generic Unsplash editorial stock (including a cat photo mid-page under "Our promise"). Replacing these with real product/brand photography would immediately lift the "authentic USA sourcing" positioning.
- Preorder cards show two large "Advance / Balance on arrival" boxes on every card, which is heavy at grid scale. Consider collapsing to a single line ("50% now · 50% on arrival") on the card and keeping the full breakdown in the quick-view.
- The cart drawer requires a shade/size but doesn't signal that until checkout. Surface the variant field as clearly required (asterisk + inline hint) inside the drawer.
- Add a visible sign-in entry benefit ("track orders, faster checkout") — right now "Sign in" is unexplained and, given the OTP bug, dead-ends.

**Admin portal**
- Strong information architecture already. Biggest win: the "Demo data" banner and "Production readiness" checklist should link directly to the exact Settings field that needs fixing (bank, support WhatsApp, shipment ETA) rather than just naming them.
- Order table's status column is dense; a compact colored status pill per row (matching the storefront tracking colors) would speed scanning.

**Ads portal**
- Clean and honest about the connection error. Once Meta is connected, add an empty-state illustration/CTA to the Campaigns and Creatives tabs (currently just text).

## 4. Config / infra actions (outside code — for the owner)

These are not code bugs; they're production-readiness items visible in the portal's own checklist:

1. **Enter real bank details** in the Supabase `store_settings` row (bank, account title, account number, IBAN).
2. **Run the auth/OTP table migration** so `otp_codes` and `team_sessions` exist — this fixes sign-in *and* makes the new admin-auth validation fully effective.
3. **Set the support WhatsApp number** in settings (several fallbacks currently point at a demo number).
4. **Set the next shipment ETA** so preorder cards show a real batch date.
5. **Replace demo product images** — 59 products still use placeholder imagery (flagged in the portal banner).
6. **Grant Meta `ads_management` / `ads_read`** permission and assign the ad account to the system user to bring the ads dashboard online.
